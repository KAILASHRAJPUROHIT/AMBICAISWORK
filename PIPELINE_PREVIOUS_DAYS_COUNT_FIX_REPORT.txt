ROOT CAUSE
- Backend /api/invoices/live-feed used a global limit(50), ordered by ingested_at desc.
- Frontend then applied liveFeed.slice(0, 8) before grouping by invoice_date.
- This produced a double truncation:
  1. The backend global limit starved older dates, so 2026-06-02 had only 5 of 22 database records in the API response.
  2. The frontend global slice kept only the first 8 records total before grouping, so previous-day groups could show only 1 row even when the API had more records.

FIX
- Backend:
  Added read-only query params to /api/invoices/live-feed:
  days=7
  per_day=20
  The endpoint now selects candidates within the requested date window and caps rows per invoice date instead of applying one global cap.
- Frontend:
  Dashboard now requests /api/invoices/live-feed?days=7&per_day=20.
  Removed global liveFeed.slice(0, 8) before grouping.
  Groups now count all returned records per date.
  Latest date shows 5 rows by default.
  Previous date groups show 10 rows by default.
  Collapsed headers show "YYYY-MM-DD — x of y shown".
  Each collapsed group has Expand.
  Open Full Pipeline toggles all returned records visible.
