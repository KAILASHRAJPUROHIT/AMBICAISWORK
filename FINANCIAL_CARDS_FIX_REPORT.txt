ROOT CAUSE
- The running backend currently returns old collection field names:
  totalCollection, cashCollection, bankCollection, chequeCollection.
- DashboardPage was rendering only newer field names:
  totalSaleToday, cashInHandToday, bankConfirmedToday, chequesPendingToday.
- Those newer fields are absent from the live JSON until the backend process is restarted with the read-only aggregate additions.
- DashboardPage also used financialDataAvailable to decide whether to show money or "Data unavailable".
- The live JSON does not include financialDataAvailable, so legitimate backend values of 0 were rendered as "Data unavailable".

FIX
- Financial cards now use fallback mapping:
  Total Sale -> totalSaleToday, fallback totalCollection
  Cash In Hand (After Opening) -> cashInHandToday, fallback cashCollection
  Bank Confirmed (Live) -> bankConfirmedToday, fallback bankCollection
  Cheques Pending -> chequesPendingToday, fallback chequeCollection
- The cards now show "Data unavailable" only when /api/dashboard/live itself is unavailable.
- If the API succeeds and a value is legitimately 0 or absent, the card renders ₹0.
