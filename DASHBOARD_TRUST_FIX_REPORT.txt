ROOT CAUSE OF ZERO FINANCIAL CARDS
- Existing dashboard cards mapped to totalCollection/cashCollection/bankCollection/chequeCollection.
- Those values were computed from PaymentModel rows attached to bills where invoice_date equals the server current date.
- The current server date is 2026-06-05, but the latest real invoice data in the local database is 2026-06-04.
- Existing bills/feed data therefore loaded correctly while strict "today" collection fields were legitimately zero for 2026-06-05.
- Added read-only aggregate fields with explicit names and financialDataAvailable/latestOperationalDate so the UI can show Data unavailable instead of a misleading money zero when no current-day financial data exists.
- No values are faked and no payment statuses or financial records are changed.

ROOT CAUSE OF WATCHER OFFLINE/PDF CONTRADICTION
- The watcher card previously used watcher_running alone to decide Online vs Offline.
- /api/admin/ingestion-status exposes both path_exists and watcher_running.
- A reachable share with watcher_running=false is not the same as Offline.
- The UI now classifies:
  Green / Online = path_exists true and watcher_running true
  Yellow / Share Reachable, Watcher Paused = path_exists true and watcher_running false
  Red / Offline = path_exists false
- The card now also shows PDF count, Last Scan, Processed, Failed, and last_error.
