Backend changes:
- OTP verify now returns password_reset_required at the top level.
- OTP verify user object also includes password_reset_required and legacy reset_required.
- /api/auth/me now returns password_reset_required and reset_required.
- Added POST /api/auth/change-password.
- change-password requires X-Session-Token.
- change-password validates:
  - current password verifies
  - new password and confirm password match
  - new password is different from current password
  - minimum password policy is met
- change-password stores only hashed_password.
- change-password sets password_reset_required=false.
- change-password audit logs PASSWORD_RESET_COMPLETED.
- Protected /api/* routes now return 403 with password_reset_required=true while the session user still has password_reset_required=true.

Frontend changes:
- Login with temp password still proceeds to OTP.
- After OTP verify, frontend stores the session and checks password_reset_required.
- If password_reset_required=true, frontend routes to /change-password.
- Added forced Change Password screen.
- No skip button is present.
- Logout option is available.
- After successful password change, local reset-required state is cleared and user is routed to Dashboard.
- Protected route guard redirects reset-required sessions to /change-password.
- Protected route guard redirects non-reset-required users away from /change-password.
- Plaintext passwords remain only in transient form state during submission.
- No password hashes are displayed.
