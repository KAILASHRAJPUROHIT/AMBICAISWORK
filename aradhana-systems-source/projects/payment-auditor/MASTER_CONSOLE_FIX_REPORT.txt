MASTER CONSOLE FIX REPORT

Root cause:
- Master Console previously fetched all owner/admin data in one Promise.all path and rendered without per-section failure handling.
- The live admin endpoints did not return usable data:
  - /api/admin/users returned 422.
  - /api/admin/security/stats returned 422.
  - /api/admin/system/mode returned 422.
  - /api/admin/financial/health returned 404.
- The 422 responses are backend dependency failures: the response asks for missing query parameters r and d even though X-Session-Token is present.
- The financial health route exists in source, but the live route is effectively not reachable and returns 404.
- A possible render crash existed at securityStats?.recent_events.map(...) because recent_events was not guarded as an array.

What changed:
- Replaced all-or-nothing Promise.all JSON parsing with independent fetch handling per section.
- Added section-level errors:
  - Unable to load user administration
  - Unable to load security stats
  - Unable to load financial health
  - Unable to load emergency controls
- Normalized users to an array before rendering.
- Normalized security stats and guarded recent_events as an array.
- Added safe fallback fields for security access logs.
- Disabled maintenance mode toggle when system mode cannot be loaded.
- Preserved existing frontend RBAC route guard for owner/admin only.

RBAC confirmation:

- Sidebar still exposes Master Console only for admin/owner.
