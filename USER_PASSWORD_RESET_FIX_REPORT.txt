USER PASSWORD RESET FIX REPORT

Branch:
- feature/password-reset-fix

Scope:
- Password reset and temporary password handling only.
- Did not touch reconciliation, dashboard, reports, LAN server, void bill, payment logic, or financial records.

Backend changes:
- New user creation now generates a secure temporary password when no temp password is supplied.
- New users always store only hashed_password.
- New users always get password_reset_required=true.
- Create user response returns temporary_password once for owner handoff.
- Admin password reset now always generates a fresh secure temporary password.
- Admin password reset stores only the new hash.
- Admin password reset sets password_reset_required=true.
- Admin password reset logs PASSWORD_RESET_TRIGGERED with no secret values.
- Self-service reset now clears password_reset_required=false after OTP verification and password update.
- Self-service reset logs PASSWORD_RESET_COMPLETED with no secret values.
- Password hashes are never returned in safe user responses.

Frontend changes:
- UserManagementDialog displays a generated temporary password once after create/reset.
- Dialog includes a clear copy warning:
  - store securely now
  - value will not be shown again
  - password hashes are never exposed
- Admin reset no longer accepts or sends a manually entered temp password.
- Existing passwords and password hashes are never displayed.

Tests updated:
- New user without temp password receives generated temporary password.
- Generated temp password matches stored hash but hash is not returned.
- Admin reset generates new temp password, updates hash, sets reset required, and logs PASSWORD_RESET_TRIGGERED.
- Self reset clears password_reset_required and logs PASSWORD_RESET_COMPLETED.
