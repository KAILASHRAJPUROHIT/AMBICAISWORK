LIVE_FEED_CLEANUP_REPORT

1. Root Cause:
Test records, particularly those generated by automated tests (e.g., `test_invoice_lifecycle.py`), were creating records with `bill_number` values like `TEST-ARCH-*` and lacking proper timestamps. The `/api/invoices/live-feed` endpoint did not filter out these synthetic bill numbers. In addition, when `invoice_date` was missing, it defaulted strictly to `"Unknown Date"` without attempting to find alternative operational dates.

2. Filter Rules Implemented:
The following filters have been applied to the `candidate_bills` query in `/api/invoices/live-feed` (inside `backend/review_api.py`):
- `~Bill.bill_number.like('TEST-%')`
- `~Bill.bill_number.like('ARCH-%')`
- `Bill.is_test_data == False` (already present)

*(Note: `employee_id LIKE 'TEST-%'` was specified in requirements, but `employee_id` does not exist on the `Bill` model or in the `live-feed` query logic, so the `TEST-%` and `ARCH-%` rules on `bill_number` alone successfully isolate the operational pipeline data).*

3. Records Removed from Dashboard:
Any `Bill` matching the new filters will no longer be retrieved for the dashboard's live feed. This eliminates synthetic test and archive generation records (e.g., `TEST-ARCH-*`).

4. Date Field Used (Fallback Order):
The date grouping logic has been updated to evaluate the following fallback order to ensure no data is grouped under `"Unknown Date"` unless absolutely missing everything:
1. `Bill.invoice_date`
2. `Bill.order_date`
3. `Bill.invoice_generated_at`
4. `Bill.created_at`

Since `Bill.created_at` falls back to the database insertion time (`func.now()`), the date will now never be null. 

5. Verification:
The dashboard live feed logic now inherently groups all records under valid calendar dates, and excludes any synthetic records with `TEST` or `ARCH` prefixes. Code changes strictly adjusted query parameters and logic without deleting or touching any underlying database records.
