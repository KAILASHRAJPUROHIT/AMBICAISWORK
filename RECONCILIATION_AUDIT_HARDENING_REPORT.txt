Difference logic
- difference is calculated as invoice_amount - total_received.
- total_received is calculated from payment rows when present.
- If payment rows are unavailable, display uses read-only bill receipt summary fields.
- stale remaining_amount is not used for display difference.

Confidence logic
- HIGH: invoice_amount == total_received and total_received > 0.
- MEDIUM: total_received > 0 and total_received < invoice_amount.
- LOW: total_received == 0, overpaid, mismatch, risk, or ambiguous.
- Confidence is deterministic and no longer hardcoded across rows.

Payment timeline
- Drawer shows each payment separately when payment rows exist.
- Each payment includes amount, mode, timestamp, UTR/reference, source, evidence_link, and evidence availability.
- Missing evidence displays "No evidence recorded".

Running totals
- Drawer shows Invoice Amount, Total Received, Outstanding, and Overpaid.

Status explanation
- Fully matched rows show the fully matched explanation.
- Partial rows show outstanding balance explanation.
- Zero-payment rows show pending-bank explanation.
- Mismatch/overpaid/risk rows show evidence-conflict explanation.
- Cheque rows show clearance-pending explanation.
- Unknown status falls back to "Review required."

Audit metadata
- Drawer shows created_at, updated_at, verified_at, verified_by, source_system, and review_age.
- Missing values display "Not Recorded".
